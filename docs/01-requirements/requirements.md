# 需求基线（Requirements Baseline）

> 来源：《汽车总线测试平台技术解决方案（集成版 v3.0）》第 2 章。
> 需求编号规则：`REQ-<域>-<序号>`，域 = `BUS`（总线）/ `SIM`（仿真）/ `SCR`（脚本）/ `DIAG`（诊断）/ `TST`（测试闭环）/ `PRD`（产品）/ `DEF`（缺陷）/ `NFR`（非功能）。

## 1. 功能需求

### 1.1 总线监控分析（BUS）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| REQ-BUS-001 | 8 通道报文 Trace 监控（CAN/CAN FD/CAN XL/LIN） | 聚合吞吐 ≥ 50k msg/s 不丢帧 |
| REQ-BUS-002 | 信号解析（DBC/LDF 数据库驱动） | 物理值/原始值正确还原 |
| REQ-BUS-003 | Graphics 绘图与 Statistics 统计视图 | 10 万点滚动不卡顿 |
| REQ-BUS-004 | 离线分析（BLF/ASC/MF4/CSV 日志回放） | 与在线行为一致 |
| REQ-BUS-005 | 物理层示波器（FPGA 1GS/s 采样） | 256KB 环形缓冲可查看波形 |

### 1.2 收发与注入（BUS）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| REQ-BUS-010 | 报文发送 / 周期发送 / 突发发送 | 周期抖动 < 100µs |
| REQ-BUS-011 | 错误帧注入（位/CRC/ACK/填充/毛刺） | 逐位级精度 |
| REQ-BUS-012 | 回环 / 监听模式 | 与硬件行为一致 |

### 1.3 仿真建模（SIM）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| REQ-SIM-001 | 剩余总线仿真（RBS）确定性事件循环 | 1ms 基准时隙 + 高精度补偿 |
| REQ-SIM-002 | 节点行为模型（Python 定义） | on_message/on_signal 回调语义 |
| REQ-SIM-003 | 调度表驱动（周期/事件/突发） | LDF/CAN 矩阵调度表可执行 |
| REQ-SIM-004 | 交互式生成器（IG） | 运行中动态启停、信号拖拽修改 |
| REQ-SIM-005 | 回放叠加仿真（Replay + RBS） | 录制日志上接入虚拟节点 |

### 1.4 脚本自动化（SCR）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| REQ-SCR-001 | Python DSL（on_message/on_timer 等装饰器） | 与 CAPL 事件语义对齐 |
| REQ-SCR-002 | CAPL 兼容函数库（output/setSignal/getSignal/write 等） | 等价行为 |
| REQ-SCR-003 | 脚本 IDE（补全/断点/单步/监视） | 可调试 |
| REQ-SCR-004 | .can 存量工程导入器 | CAPL → Python 转换（规划） |

### 1.5 诊断能力（DIAG）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| REQ-DIAG-001 | UDS 全服务 + OBD-II + LIN 诊断 | 服务/子功能全量 |
| REQ-DIAG-002 | Seed&Key 插件化（算法脚本热加载） | 安全访问 |
| REQ-DIAG-003 | 刷写流程状态机（预编程→擦除→写入→校验→跳转） | 断点续传 |
| REQ-DIAG-004 | DTC 管理（读/清/冻结帧）+ ODX 引擎 | ODX/PDX 解析 |

### 1.6 测试闭环（TST）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| REQ-TST-001 | 用例编辑器（图形流程 + 步骤表格双模式，IR 唯一真源） | 双向同步零丢失 |
| REQ-TST-002 | 用例库管理（目录/标签/检索/版本/评审流） | 100 条用例可管理 |
| REQ-TST-003 | Test Runner 执行引擎（串并行/断言库/四态判定） | 8 通道并发，断言精度 < 1ms |
| REQ-TST-004 | 报告系统（HTML/PDF/Excel/Word + 双语模板） | 千级用例 < 5s |
| REQ-TST-005 | 失败现场追溯（期望 vs 实际 + 前后 500ms 波形） | 一键直达缺陷 |

### 1.7 产品管理（PRD）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| REQ-PRD-001 | 产品档案（名称/型号/ECU 类型/软硬件版本/VIN 规则/生命周期） | CRUD + 状态机 |
| REQ-PRD-002 | 车型适配矩阵（平台 × 车型，DBC/LDF 版本覆盖预警） | 矩阵驱动参数化测试计划 |
| REQ-PRD-003 | 资源包绑定（按车型切换 DBC/LDF/ODX，SHA-256 校验） | 零错误切换 |
| REQ-PRD-004 | 产品基线冻结（快照可复现） | 任意历史基线可重建 |

### 1.8 结果与缺陷（DEF）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| REQ-DEF-001 | 测试批次 Test Run 模型 + 逐用例结果 | 四态 + 断言详情 + 附件 |
| REQ-DEF-002 | 质量指标趋势（通过率/FPY/缺陷密度/回归率） | 图表 + CI 质量门禁 |
| REQ-DEF-003 | BUG 全生命周期跟踪（S0-S3 × P0-P3 矩阵 + 状态机） | 审计留痕 |
| REQ-DEF-004 | 一键建单（失败现场自动打包 → 缺陷草稿） | 10 秒内生成 |

## 2. 非功能需求（NFR）

| 编号 | 指标 | 目标值 | 验收方式 |
|---|---|---|---|
| REQ-NFR-001 | 聚合帧吞吐 | ≥ 50,000 msg/s | 8 通道满负载压测 |
| REQ-NFR-002 | 接收时间戳 | 100 ns | 差分信号校准 |
| REQ-NFR-003 | 端到端延迟 | < 1 ms | 硬件注入-软件收到打点 |
| REQ-NFR-004 | 发送周期抖动 | < 100 µs | 示波器统计 |
| REQ-NFR-005 | 日志吞吐 | ≥ 100 MB/s | BLF/MF4 满速写入 |
| REQ-NFR-006 | UI 刷新率 | 60 fps（16ms 批渲染） | 帧率监控 |
| REQ-NFR-007 | 长时间稳定性 | 72h 内存零增长 | soak 测试 |
| REQ-NFR-008 | 跨设备同步 | < 1 µs（PPS+同步帧，4 设备级联） | 同步帧偏差测量 |

## 3. 需求-模块映射

| 需求域 | 硬件模块 | 软件模块 | 管理模块 |
|---|---|---|---|
| 总线监控 | FPGA 过滤 + 打戳 | Trace / Graphics / Statistics | — |
| 错误注入 | FPGA 注入器 | 注入面板 + 脚本 API | — |
| 剩余总线仿真 | 硬件发送调度器 | RBS 引擎 + IG + 节点模型 | — |
| 诊断 | — | UDS 栈 + ODX + Seed&Key | — |
| 自动化测试 | — | Test Runner + 断言库 | 用例库 / 报告系统 |
| 产品维度测试 | — | — | 产品中心 + 车型矩阵 |
| 缺陷闭环 | — | 一键建单插件 | 缺陷中心 + 结果管理 |
